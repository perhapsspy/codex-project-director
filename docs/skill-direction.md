# 스킬 방향

## 목적

여러 Codex 과제나 세션을 하나의 검증된 프로젝트 결과까지 이끄는, 직접 구현하지 않는 능동적 조정 계층을 제공한다.

## 설계 원칙

- 디렉터는 프로젝트 결과와 흐름을 능동적으로 맡되 제품 코드, 담당 영역의 구현과 디버깅은 맡지 않는다.
- 사용자가 현재 세션을 디렉터나 감독자로 명시하면 자연어로 적용할 수 있고 `$codex-project-director`로도 직접 호출할 수 있다.
- 최신 사용자 승인 기준과 교정은 지속 목표, 상태 문서와 모든 작업·검토 결과보다 우선하며 중대한 이탈에는 명시적 사용자 승인이 필요하다.
- 명시적으로 지정된 디렉터 세션은 같은 프로젝트 결과의 지속 목표(Goal) 하나를 유지한다. 지속 목표는 실행을, 짧은 디렉터 상태 문서는 현재 행동과 대기를 맡는다.
- 디렉터 상태 문서는 기존 문서 규칙을 따르되 기본은 `docs/director-state.md`이며 `Goal`, `Now`, `Waiting`, `Constraints`만 현재 상태로 덮어쓴다.
- 감독은 사건에 반응하고, 사건이 오지 않는 사실을 따로 관찰할 수 있을 때만 점검 시점을 둔다.
- 경계가 정해진 결과와 변경 영역에는 담당자 한 명을 기본으로 둔다. 공유 계약, 실행 영향, 의존성, 되돌림 경계와 변경 영역이 독립인 작업만 이익이 조정 비용보다 클 때 병렬화하며 공유 통합은 담당자 한 명이 맡는다.
- 막힘은 현재 담당자 지원, 범위가 정해진 보조 담당자, 독립 작업 분리, 명시적 담당자 교체 순으로 복구한다.
- 완료는 간결한 증거와 위험에 비례한 독립 검증으로 판단한다.
- 실제 피해의 신뢰할 만한 첫 증거가 나오면 해당 영역의 추가 변경을 멈추고 승인된 복구 경로를 우선한다.
- 검증 주기는 시험 방식이 아니라 승인 주장과 실행 영향으로 정한다. 위험한 실행에는 실행 전 필수 검토와 승인된 안전 관문을 유지한다.
- 격리되고 되돌릴 수 있는 작업은 가장 작은 반증 범위에서 반복하고, 관련 변경을 묶어 위험에 맞는 이정표에서 검토한 뒤 검토된 최종 변경분에 필요한 넓은 검증을 수행한다.
- 승인 사실마다 정본 증거 출처 하나를 두며, 독립 증거가 모순되면 출처·최신성·적용 범위를 대조해 해소할 때까지 승인을 보류한다.
- 결함 증거와 제안 해법을 분리하고 기존 담당자와 계약 안의 가장 작은 해법을 우선한다. 사용자 승인 계약의 정확한 식별자와 경로는 인계에서 그대로 보존한다.
- 사용자 교정과 충돌하는 작업만 멈추고 낡은 지시와 승인 주장을 철회한다. 영향 담당자가 변경 중단과 교정된 계약을 확인한 뒤 재개하며 독립 작업은 계속 진행한다.
- 같은 승인 경계가 새 증거 없이 반복되거나 여러 사건에도 진전이 없으면 영향을 받는 작업의 수정을 멈추고 가정, 담당자, 승인 질문, 정본 증거, 대표 검증과 검토 주기를 다시 정한다. 다른 독립 작업은 계속 진행한다.
- 세션 교훈은 권한이 아니라 범위가 정해진 가설이며, 재사용할 조정 규칙은 반복 실패와 독립 사전 검증 뒤에만 승격한다.

## 경계

- 작업자는 조사, 구현, 담당 영역의 디버깅과 검증을 맡는다.
- `reviewer`와 `decision reasoner`는 독립 검증이나 고비용 결정을 별도로 맡길 가치가 있을 때만 사용한다.

## 변경 기준

다음 실패가 실제 디렉터 세션에서 재현될 때만 운영 계약을 바꾼다.

- 지속 목표가 있는데도 실행이 멈추거나 점검이 과잉 감시로 변한다.
- 복구 과정에서 구현을 넘겨받거나, 같은 영역의 변경 담당자가 겹치거나, 인계가 불완전하다.
- 호출·제외·증거 계약 때문에 과잉 발동, 미발동 또는 잘못된 완료 판단이 반복된다.
- 조정 비용이 방지한 재작업보다 커진다.

변경은 실제 디렉터 세션과 독립 사전 검증으로 확인하고 별도의 배포 관문을 통과한다.
