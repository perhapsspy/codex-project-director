# 스킬 방향

## 목적

여러 Codex 과제나 세션을 하나의 검증된 프로젝트 결과까지 이끄는 능동적이고 비구현적인 조정 계층을 제공한다. 구체적인 실행 계약은 `skills/codex-project-director/SKILL.md`가 소유한다.

## 핵심 방향

- 디렉터는 승인된 해결책·담당 경계·사용 경로·완료 상태를 한 문장으로 유지하고, 작업자·검토자·분석자의 제안을 그 안에서 프로젝트 결정으로 통합한다.
- 구조·계약 정본, 변경 담당과 `Action Scope`를 별도로 판단한다. 새 발견은 현재 담당자에게 남기고, 기존 레코드 밖의 변경 제안만 결정 전까지 읽기 전용으로 둔다.
- 디렉터는 프로젝트 흐름, 작업 간 계약, 증거와 통합을 맡고 구현은 사용자 가시 작업자가 맡는다. 목적이 맞는 기존 작업자를 우선하며 새 작업자는 사용자가 명시적으로 요청할 때만 시작한다.
- 저장소 간 변경은 현재 소스에서 정본 관계와 기존 wire를 먼저 확인한다. 변경 영역에는 담당자 한 명을 두고, 병렬 작업은 공유 target contract가 안정된 뒤 실행 영향, 의존성, 되돌림과 변경 영역이 독립이고 조정 비용보다 이익이 클 때 사용한다.
- 내부 에이전트는 범위가 정해진 조사·검증·결정만 지원한다. 디렉터는 결과·제약·증거를 지휘하고 구현 판단은 변경 담당자에게 맡긴다.
- Goal은 지속성을 제공하고 권한은 제공하지 않는다. 사용자가 독립 분리한 작업은 감독과 완료 판단에서 제거한다.
- 감독은 다음 사건과 판단 시점을 기준으로 움직인다. 정상 실행은 기다리고, 근거 없이 멈춘 작업은 한 번의 집중 확인과 같은 범위의 복구 뒤 명확한 상태로 전환한다.
- 복구는 승인된 경계와 기존 담당 체계 안에서 수행한다. 국소 변경, push, PR, 배포, 실서비스 변경, credential 변경과 데이터 삭제는 승인된 `Action Scope`에 명시적으로 포함한다.
- 완료는 최근 승인된 사용자 경로의 직접 증거, 통합 결과와 모든 담당 작업의 종료로 판단한다. 조정 문서는 쓰기 권한이 있을 때만 기존 정본을 재사용해 작게 유지한다.

## 진화 기준

운영 계약은 실제 디렉터 세션에서 다음 문제가 반복되고 독립 사전 검증으로 개선안을 확인했을 때 바꾼다.

- 승인 밖의 작업 생성이나 독립 분리된 작업의 재개
- 수동적 방치 또는 정상 작업에 대한 과잉 개입
- 구현 인수, 담당 중복 또는 불완전한 인계
- 지나치게 작거나 겹치는 작업 분리와 국소 의견의 방향 점유
- 불충분한 증거에 따른 완료 또는 위험한 실행

변경은 별도의 배포 관문을 통과한다.
