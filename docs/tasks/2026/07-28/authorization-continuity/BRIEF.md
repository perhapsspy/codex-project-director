# 승인 연속성과 수정본 검증

## Goal

- 디렉터가 이미 승인된 되돌릴 수 있는 국소 수정과 수정된 판본의 검증을 새 권한 요청으로 잘못 올리지 않으면서 기존 안전 관문을 보존하도록 실행 계약을 교정한다.

## Scope

- 승인 기록의 동일성, `retry0` 의미, 작업자 보고의 재분류와 사용자 질문 경계만 다룬다.
- 일반 자율성 확대, 위험한 실행의 정확히 한 번 효과 완화와 새 승인 저장 형식은 포함하지 않는다.

## Current Facts

- 실제 운용에서 국소 제품 원천 오류 수정, 로컬 확인과 수정된 판본의 새 대표 검증이 매 단계 사용자 승인으로 잘못 승격됐다.
- 현재 스킬은 위험한 실행 관문과 국소 작업자 소유를 규정하지만 새 판본과 새 권한의 차이, 승인 요청 전 필드 변화 증명을 명시하지 않는다.
- 사용자 교정은 `Outcome`, `Surface`, `Effect`, `Owner`가 모두 같으면 같은 원인·담당자·되돌림 경계의 수정과 새 판본 검증 1회를 기존 권한의 연속으로 보라는 것이다.

## Current State

- 한영 실행 계약과 설계 방향의 최소 교정 후보가 스킬 형식과 변경분 검사를 통과했다. 네 개의 맥락 비상속 회귀 시나리오에서 국소 수정본 검증과 작업자 종료 문구는 무질문 연속 작업으로, 무변경 `retry0` 반복은 실행 중단·담당자 반환으로, `WinSta0` 전환은 필드 변화를 밝힌 사용자 결정으로 분류됐다.

## Next Step

- 검증된 후보를 정본 작업 트리에 적용하고 한영 정합성과 스킬 형식을 다시 확인한 뒤 사용자 검토용 변경안으로 보고한다.
